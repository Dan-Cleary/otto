how it works // three steps

flag → pr

01
widget / in-app

your team flags it

drop the otto widget on your qa or prod build. anyone on your team can submit a bug or feedback in two clicks — text, page url, recent console errors.

02
extract / route

otto thinks

otto extracts the request, finds the relevant repo and file, and decides whether the change is small enough to draft on its own.

03
diff / branch

otto drafts

a draft pr lands in github with the original report attached. you review, tweak, merge — or hand it back. otto never auto-merges.

get started // early access

wake otto up.

drop the otto widget in your app and otto starts drafting prs from every report. read-only by default — every diff waits for a human.
